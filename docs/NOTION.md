# Notion에 평가 결과 저장하기

원본 hiring-panel 스킬을 변경하지 않고 별도 API 업로드 도구를 추가했습니다. 완료된 평가 폴더의 `PANEL.md`와 `RESUME-IMPROVED.md`만 읽어 지정한 상위 페이지 아래에 새 하위 페이지를 만듭니다. 원본 PDF는 전송하지 않습니다. 두 문서에는 개인정보가 있을 수 있으므로 저장할 워크스페이스와 공유 범위를 먼저 확인하세요.

## 1. API 연결 준비

ChatGPT 앱의 Notion 연결과 이 Python 도구의 API 인증은 별개입니다.

1. https://www.notion.so/profile/integrations 에서 저장할 워크스페이스의 내부 통합(Internal integration)을 만듭니다. 관리 권한이 없다면 워크스페이스 관리자에게 요청하세요.
2. **콘텐츠 읽기(Read content)**와 **콘텐츠 삽입(Insert content)** 권한을 켭니다.
3. Notion 상위 페이지에서 `··· → 연결(Connections) → 연결 추가`를 열어 이 내부 통합을 추가합니다. 통합의 Content access 설정에서 페이지를 선택하는 UI가 나오면 해당 페이지를 허용합니다. ChatGPT 연결만 허용하는 것으로는 API 통합 권한이 생기지 않습니다.
4. 내부 통합 토큰은 클라우드 환경 설정의 비밀값 **`NOTION_TOKEN`**에 입력합니다. 채팅·GitHub·스크립트에 넣지 마세요. 이 도구는 토큰을 환경변수로만 읽습니다.
5. 환경변수 **`NOTION_PARENT_PAGE_ID`**에 상위 페이지 ID를 설정합니다. `--parent` 인자로 Notion 페이지 링크를 직접 지정해도 됩니다.
6. 제한된 네트워크에서는 **`api.notion.com`** HTTPS 접근을 허용합니다. 클라우드 설정 초안에 요구사항을 저장했으며, 설정을 검토·저장하고 환경을 게시해야 새 환경에 반영됩니다. 실제 실행 환경에 토큰·네트워크 설정이 적용됐는지 별도로 확인해야 합니다.

데이터베이스/데이터 소스가 아닌 **일반 페이지**를 상위로 사용합니다. 사용자별 저장 페이지 값은 GitHub에 기록하지 않습니다.

## 2. 읽기 권한 확인

```bash
python3 scripts/notion_export.py --check
```

성공하면 토큰이 해당 상위 페이지를 읽을 수 있습니다. 쓰기 권한은 실제 업로드가 성공해야 확인됩니다. 401은 인증, 403은 네트워크 또는 통합 권한, 404는 페이지 ID·공유 설정을 확인하세요. 설정 변경 후 같은 명령으로 다시 확인합니다.

## 3. 전송 전 로컬 검증

```bash
python3 scripts/notion_export.py '.hiring-panel/날짜-이름' --dry-run
```

토큰 없이도 동작하며 네트워크 요청·파일 변경 없이 두 결과 파일의 존재, Notion 블록·용량 제한을 검사합니다. 문서 내용이나 토큰은 출력하지 않습니다. 제목·목록·인용은 기본 Notion 블록으로 변환하며 인라인 강조·표 등의 고급 Markdown은 텍스트로 유지합니다. 긴 문서는 전체 본문을 텍스트 블록으로 보존합니다.

## 4. 업로드

```bash
python3 scripts/notion_export.py '.hiring-panel/날짜-이름'
```

정상적으로 완료되면 새 Notion 페이지 링크를 출력합니다. 별도 제목은 `--title '모트라스 안전보건 지원서 검토'`로 지정합니다. 저장 위치는 설정된 상위 페이지이며 다른 페이지를 수정·삭제하지 않습니다. 자동 평가 직후 저장을 원하면 Codex에 “평가가 끝나면 이 폴더를 Notion에 저장해 줘”라고 명시적으로 요청하세요. 기본 평가 동작에서 자동으로 개인정보를 외부 전송하지 않습니다.

## 중복 및 실패 처리

- 성공한 업로드는 평가 폴더의 `.notion-upload.json`에 페이지 ID·URL·문서 해시만 기록합니다. 비밀값은 저장하지 않습니다.
- 동일 내용·위치의 재실행은 기존 URL만 반환합니다.
- 기존 내용을 수정한 뒤 재업로드하는 경우에는 새 평가 폴더를 사용하세요. 기존 Notion 페이지를 덮어쓰지 않습니다.
- 타임아웃·연결 끊김·서버 오류는 실제 생성 여부가 불확실하므로 `pending` 기록을 유지하고 자동 재전송하지 않습니다. 먼저 Notion 상위 페이지에서 생성 여부를 확인하세요. 페이지가 없다면 해당 폴더의 `.notion-upload.json`을 백업한 뒤 제거하고 다시 실행할 수 있습니다. 페이지가 있다면 새로 만들지 말고 그 페이지를 사용하세요.
- Notion의 명시적인 400/401/403/404/409/422/429 응답은 생성 거부로 처리하므로 설정을 고친 후 재시도할 수 있습니다.
- 네트워크 장애를 이유로 TLS 검증을 끄지 않습니다. 리디렉션에 인증 헤더를 전달하지 않으며 POST 요청을 자동 재시도하지 않습니다.

## API 및 검증 범위

Notion 공식 SDK의 기본 버전과 같은 **2025-09-03** API를 사용합니다. 공식 SDK 출처: https://github.com/makenotion/notion-sdk-js/blob/main/src/Client.ts

```bash
python3 -m unittest discover -s tests -v
```

오프라인 테스트는 페이지 링크 파싱, 한글·이모지 무손실 분할, 문서 변환, 중복 방지, 불확실한 요청 실패 후 재전송 차단, 권한 수정 후 재시도, 토큰 비노출 등을 검증합니다. 이는 실제 Notion 저장 성공을 대신하지 않습니다. 실제 업로드는 환경 토큰·네트워크·페이지 접근이 준비된 후 별도로 검증합니다.
